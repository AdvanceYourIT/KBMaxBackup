Maintenance and feature release.

## What is new since 1.0.0
- Records that are too large for one Azure DevOps push (above about 16 MB) are no longer lost: they are collected in a small second ZIP, `<backup>_too-large-files.zip`, that is downloaded automatically at the end of the run.
- Incremental sync no longer reports a stored file that is empty or not valid JSON as a "rejected token"; such a file is simply replaced.
- The download package is smaller: it contains only the files the extension needs to run, plus the README, LICENSE and `INSTALL.txt`. Setup guides, examples and the KBMax API notes stay in the repository.
- Releases are published by a GitHub Actions workflow when a version tag is pushed.

## Install
Download **KBMax-Backup-v1.1.1.zip** below and unzip it. Open `edge://extensions` (or `chrome://extensions`), enable **Developer mode**, click **Load unpacked** and select the unzipped folder (the one that contains `manifest.json`).

This is an unofficial community tool, not affiliated with Epicor. It uses KBMax's internal, undocumented web API: try it on a DEV environment first.
